# 푸시 알림 설정 체크리스트 (편지·답장 도착 알림)

앱인토스 푸시는 **"기능성 메시지(스마트 발송)"** 로 보내요. 콘솔에서 아래 3가지를 먼저 등록하고,
발급된 **코드들을 개발자에게 전달**하면 코드 연결(Edge Function + 트리거 + 동의 요청)을 마무리해요.

> 푸시는 **실제 토스 로그인 유저 + 토스 앱 안에서만** 도착해요. 브라우저/둘러보기(익명) 유저에게는 가지 않아요.

---

## 1단계. 알림 수신 동의문 등록
사용자에게 "알림 받을래요?" 동의를 받기 위한 문구예요.

- 콘솔 → **스마트 발송 → 알림 동의문** → 새 동의문 등록
- 제안 문구:
  - 제목: `돛단배 알림 받기`
  - 내용: `새 편지나 답장이 도착하면 알려드릴게요.`
- 👉 발급되는 **동의문 템플릿 코드** 를 받아두기 (예: `agree_xxx`)

## 2단계. 기능성 캠페인 + 메시지 템플릿 2개 등록 + 문구 검수
실제로 발송할 푸시 문구예요. **2개**(편지 도착 / 답장 도착)를 등록하고 **검수 승인**까지 받아야 해요.

- 콘솔 → **스마트 발송 → 캠페인(기능성)** 생성

**① 새 편지 도착**
- 제목: `🍾 새 편지가 도착했어요`
- 내용: `바다 건너 누군가 편지를 보냈어요. 지금 확인해보세요.`
- 템플릿 변수(context): 없음 (익명이라 동적 값 불필요)

**② 새 답장 도착**
- 제목: `💌 답장이 도착했어요`
- 내용: `내가 띄운 편지에 답장이 왔어요. 확인해보세요.`
- 템플릿 변수(context): 없음

- 👉 각 템플릿의 **templateSetCode 2개** 를 받아두기 (예: `bottle_arrived`, `reply_arrived`)
- ⚠️ 두 템플릿 모두 **문구 검수 승인** 을 받아야 발송돼요.

## 3단계. 토스 파트너 API 인증서/키 (mTLS)
발송 API 호출에 필요해요. **토스 로그인 연동에 쓰는 인증서와 동일**해서, 이미 준비됐다면 그대로 써요.

- 필요한 시크릿(개발자가 `supabase secrets set` 으로 등록):
  - `TOSS_MTLS_CERT`, `TOSS_MTLS_KEY` (콘솔 발급 mTLS 인증서/개인키)
- 발송 엔드포인트: `POST https://apps-in-toss-api.toss.im/api-partner/v1/apps-in-toss/messenger/send-message`
- 인증 헤더: `x-toss-user-key` (수신자 토스 유저키)

---

## 개발자에게 전달할 것 (이거 주시면 바로 연결)
1. 동의문 템플릿 코드 (1단계)
2. 편지 도착 templateSetCode (2단계 ①)
3. 답장 도착 templateSetCode (2단계 ②)
4. mTLS 인증서/키 준비 여부 (3단계)

코드를 받으면 다음을 구현해요:
- 클라이언트: 로그인 후 `requestNotificationAgreement` 로 알림 동의 요청
- Edge Function `push-notify`: 토스 send-message 호출 (mTLS)
- DB 트리거: `bottles`/`replies` insert 시 수신자에게 푸시 (익명 유저·본인 제외)

---

## 참고
- 발송 제한: `send-message` 는 userKey당 분당 최대 10회
- 공식 문서: 스마트 발송 개발 가이드 / requestNotificationAgreement 레퍼런스
